## Purpose

This file separates sources that establish truth from capabilities that supply a
method. A provider may analyze or review a source; it cannot manufacture brand,
platform, product, maturity, or user facts that the source does not contain.

## Authority precedence

1. **Explicit user direction**
   - Use AliDesign with capability-level routing.
   - Preserve v1 and `round-001` as old-contract history.
   - Restart v2 from positioning and three art directions.
   - Do not continue tuning the current banner.
2. **Repository operating contract**
   - `AGENTS.md` defines workflow, authoring source, generated outputs,
     verification, accessibility surfaces, and prohibited visual patterns.
3. **Public identity and project facts**
   - GitHub profile API, public repository metadata, source trees, READMEs,
     releases, install instructions, tests, CI, and support documentation.
4. **GitHub/GFM platform constraints**
   - Static Profile README; local images; normal anchors; native Pins,
     contributions, and activity outside the README.
5. **Task-local decisions**
   - This run's brief, evidence, positioning, claim-proof map, route, and
     explicitly accepted future direction.
6. **General design guidance**
   - Useful only where it does not conflict with a more specific authority.

## Resolved conflicts

### AI identity versus evidence maturity

There is enough evidence for an action-based AI-native direction: an installable
Codex Skill, an experimental file-native workflow harness, a tested preflight
protocol, and a taxonomy draft. There is not enough evidence for “AI expert,”
“AI systems architect,” an enterprise platform, adoption, or production-grade
claims. The route therefore permits a current-direction thesis but not a senior
credential.

### Professional clarity versus project variety

The repositories remain varied. The unifying proposition is not that they form
one runtime. It is the repeated discipline of explicit intent, durable files,
gates, installation, release, tests, support boundaries, and inspectable proof.

### Three concepts versus missing art-direction authority

The user explicitly requested three new directions. The design-quality provider
may structure them as reversible hypotheses. `visual_art_direction` remains
`missing`; no concept becomes product authority until a legitimate provider and
an explicit selection are appended in a later route revision.
