# Profile v2 information architecture

Status: selected structure declaration; no production projection.
Selected from: `information-architecture-variants.md` Variant A.

## Reading spine

The Profile is one continuous editorial column. Every region has one job and
the page does not branch into a dashboard, project grid, or multi-column résumé.

### 01 — Identity and inquiry

Purpose: establish Cooper Oak, the AI workflow experimenter posture, and the
core question.

Required content:

- abstract Oak identity glyph;
- `COOPER OAK`;
- `Experiments in keeping humans in control of AI-assisted work.`

No résumé summary, role-badge wall, double CTA, or fabricated maturity label.

### 02 — Current Experiment

Purpose: provide immediate evidence for the positioning.

Required content:

- `CAPABILITY ROUTING`;
- one concise `QUESTION`;
- one falsifiable `HYPOTHESIS`;
- evidence expressed as facts and linked to a separate case;
- one `NEXT` statement that exposes incompleteness rather than marketing it.

The four fields form one open reading sequence, not four cards or statuses.

### 03 — Working Principles

Purpose: extract reusable method only after the visitor has seen a concrete
experiment.

Required content:

1. Make control explicit.
2. Route work to specialists.
3. Claims need evidence.

Each principle must point back to the case. No extra principles are added for
visual symmetry.

### 04 — Open Loop

Purpose: show one honest continuity between early experimentation and current
ability.

Required content:

- one sentence that older repositories record a path of trial and growth;
- `writing-loop-harness` only;
- the truth that it worked locally but never became a clear installable tool;
- the future closure condition, without a date promise.

### 05 — Discuss on GitHub

Purpose: give fellow builders and collaborators a contextual way to respond.

The final destination must be a real GitHub Issue, Discussion, repository, or
case context. It is native text and link behavior, never a fake button in SVG.

## Responsive transformation

- Desktop and narrow layouts remain single-column.
- The Oak glyph may move from a lateral counterweight to a top or inline anchor;
  it must not shrink into a decorative corner icon.
- Hero line breaks are composed separately for the narrow layout.
- Experiment fields remain sequential and readable at 320px.
- All critical identity, content, and links remain native text in the eventual
  Profile even when a shallow signature visual is used.

## Deferred platform regions

GitHub Pins, contributions, achievements, activity, repository counts, and the
account bio remain platform-owned. Profile v2 does not imitate, duplicate, or
visually compete with them inside the README.
