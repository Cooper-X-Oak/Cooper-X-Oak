## Root cause

The old artifact is mechanically sound but its primary silhouette is
semantically wrong. Rings, pipelines, and abstract nodes dominate; canopy,
fork, trunk, and rooted weight never form a recognizable Oak. Thin internal
logic carries more information than the outside contour, so narrow rendering
weakens the only cues that made the glyph intelligible.

The surrounding page compounds the failure. Pixel geometry appears only in a
shallow Hero strip and an Evidence marker. Native headings, rules, lists, links,
and later sections are structurally valid but visually default. The previous
contract's two-role asset allowlist and prohibition on additional page-level
visual grammar optimized against fake UI so aggressively that it also removed
the means to create an authored composition.

## Directed return

- Verdict: `needs_revision` as new user evidence, without rewriting the old
  sealed `passed` round.
- Owner phase: `component_domain`.
- Owner declaration: `visual_design.oak_monument_skeleton`, followed by the
  poster composition and page-system declarations selected in this run.
- Required correction: replace the glyph at the silhouette level, expand pixel
  geometry into the whole composition, and prove recognizable Oak identity at
  desktop and true 320px before implementation.

## First controller ruling

Use a double-shoulder, single-canopy Oak monument: one connected 4:3 silhouette
with a broad stepped crown, explicit Y fork, thick central trunk, and roots that
emerge directly without a badge or base disc. The shape must work as a single
color before typography, forest green, or internal accents are added.

Reject a cloud block, maze, circuit, mushroom, Space Invader, landscape strip,
small logo, exact game-sprite symmetry, or any design that needs the words
`COOPER OAK` to be understood as a tree.
